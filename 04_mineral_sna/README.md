# 광물–원소 네트워크 분석 (Fe · Ni)

구성 원소 정보를 이용한 광물 네트워크의 사회연결망 분석. 철(Fe)과 니켈(Ni) 두 건.

## 문제

광물 데이터베이스는 광물마다 어떤 원소로 이루어져 있는지를 문자열로만 담고 있다.
이 정보만으로 **어떤 원소들이 함께 등장하는지, 광물들이 원소 구성에 따라 어떻게 무리 지어지는지**를 볼 수 있는가.
정형 테이블을 그대로 봐서는 원소 간 관계가 드러나지 않는다.

## 접근

- `Chemistry Elements` 문자열을 공백 기준으로 분해해 전체 원소 목록을 만들고, **광물 × 원소 이진 행렬**(2-mode 네트워크)로 변환했다.
- 변환이 맞는지 확인하기 위해 **원본의 원소 개수와 행렬의 행 합을 대조**하는 검증 단계를 넣었다.
- `sna` 패키지로 2-mode 네트워크를 시각화하고, 1-mode로 투영한 뒤 계층적 군집·k-means·MDS·커뮤니티 탐지로 구조를 확인했다.
- 광물의 생성 단계(stage)와 산출 기원(origin)별로 네트워크를 나눠 그려 구조가 어떻게 달라지는지 비교했다.

## 결과

원소 동시 출현 구조에서 나타나는 군집과 중심 원소를 정리했다. 결과 그림은 각 폴더의 `이미지/`, `image/`에 있다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `fe/fe_sna.R` | 철광물 분석 **진입점** (526줄) |
| `fe/stress.R` | MDS stress 값 계산 |
| `fe/Fe Minerals_database_20250922.xlsx` | 철광물 데이터베이스 |
| `ni/code.R` | 니켈광물 분석 **진입점** (386줄) |
| `ni/label.R`, `ni/stage_sna.R` | 라벨링 · 생성단계별 네트워크 |
| `ni/sna/` | 초기 실험 코드 모음 (`comunity.R`, `2net by origin.R`, `year_bipara.R` 등) |
| `ni/Nikel mineral database_20250803 (1).xlsx` | 니켈광물 데이터베이스 |

## 실행 전 확인

두 진입점 모두 상단의 `read_xlsx()` 경로가 개발 당시 로컬 절대경로로 되어 있다.
같은 폴더의 xlsx를 가리키도록 수정해야 한다.

필요 패키지: `sna`, `readxl`, `tidyverse`, `scales`

## 정리하지 않은 부분

`ni/sna/` 아래에는 파일명이 비슷한 실험 코드가 여러 개 있다
(`stage_sna.R` / `stage-sna.R`, `code.R` 두 개, `old_sna.R`).
최종 결과는 `ni/code.R` 기준이며, 나머지는 중간 과정 기록이다.
